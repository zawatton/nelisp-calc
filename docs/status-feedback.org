#+TITLE: Canvas status feedback and post-action CPU observations

The calculation canvas previously copied every status string into its GTK
tooltip, including ordinary =ok= and calculation errors. Status already
appears inside the canvas. The canvas now disables its tooltip while retaining
status rendering, wait feedback and the existing redraw cache. Button help and
settings-save feedback are unchanged.

The theme evidence path also freed the result of
=gtk_widget_get_tooltip_text=. GTK documents that result as instance-owned;
the invalid free was removed. See the official
[[https://docs.gtk.org/gtk4/method.Widget.get_tooltip_text.html][GTK tooltip getter ownership contract]]. A native fixture set a settings-save
failure tooltip, called theme evidence twice and recovered the unchanged text
without a crash. This is not evidence that the reported CPU issue was caused
by that ownership error.
