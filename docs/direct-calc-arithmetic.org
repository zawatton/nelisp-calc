* Contract and genuine provider
The pinned GNU =calc.el= defines public =math-read-number (s &optional decimal)=
at line 3247. GNU =calc-aent.el= uses that reader for numeric factors, at line
1095. It returns precision-normalized GNU numbers. The alternative
=math-read-number-simple= explicitly preserves every digit, so it is not the
reader selected for this path. A BAF runtime probe confirmed literal-node
equivalence at precision 2, 12 and 30, including exact integers beyond both
2^53 and int64, decimal zero, leading zeros and rounded decimal mantissas.

Only two unsigned ASCII integers or decimals with digits on both sides of a
decimal point, and an operator from +, -, *, /, use direct numeric reading.
The adapter constructs the genuine GNU operator node, then uses the existing
shared =calc-normalize=, extension retry, =math-constp= and
=math-format-value= path. Result structures, errors, display/status updates,
session recording and precision bindings stay in the shared evaluator.
No host floating point, host decimal conversion, replacement arithmetic,
result caching, core/vendor changes or runtime policy changes are introduced.

Signs, negative zero, fractions, exponents, trailing dots, compound expressions,
other operations and unsupported/customized input settings retain the text
parser. Language, radix, filters and user token/parse tables are checked live.
GNU replacement/superscript/subscript settings are approved only when their
source characters cannot affect the accepted ASCII syntax. A deep snapshot,
including copied strings, allows native =equal= to detect in-place changes
without rescanning 70 GNU replacement entries for every operation. The probe
tests both string mutation and existing-cons mutation with restoration.
GNU's own preprocessing cache is refreshed in those tests because it caches
by list identity and otherwise does not recognize such in-place edits.

The contract assumes the pinned genuine provider function definitions remain
unmodified. Arbitrary =fset=/advice replacements of GNU parser/preprocessor
functions are outside this adapter's supported customization surface. The
probe temporarily wraps preprocessing solely to count calls. Its direct-path
assertion requires zero calls; fallback cases require one.

* Verification and limits
The matrix compares complete result values and display/status/expression/fresh
state against the archived path for 20 cases at precision 2, 12 and 30.
Independent exact expectations are additionally checked at precisions 12 and
30; precision 2 correctly rounds some decimal inputs/results differently.
The same genuine precision behavior is required on both paths. Cases include
large exact integers, decimals, zero and negative zero, divide-by-zero, malformed
input, rational/scientific/compound/trailing-dot fallback. Further checks cover
custom input preprocessing, all three angle modes, precision-20 square root,
engine unavailable, repeated equals and exactly matching history entries.
The final focused probe exits 0 with =DIRECT-CALC-PASS 223 checks= in
=target/direct-checked.log=. The exact final probe with archived engine exits
1 after =SEMANTICS-PASS 185=, at the intended assertion
==(= direct-preprocess-count 0)== in =target/direct-negative-final.log=.
Thus the old engine retains correct arithmetic/customization semantics but
fails the direct-path contract. The earlier timing run's 220 checks preceded
the three additional restored-cons mutation assertions; adapter source was
identical in both runs. The final probe SHA256 is
=D4396AF33960769E38C9B7402CBEAEE2D430F2836016CC57A0FAC413822153D4=.

Unchanged test sources are run directly with the explicit BAF runtime because
=tools/engine-probe.ps1= hardcodes an unrelated shared executable. The Standard,
Scientific, ScientificPrecision and genuine isqrt provider sources retain all
their assertions and PASS markers. No vendor, runtime, GUI, mailbox, session
or shared-service files are changed. Only this document, the focused probe and
the adapter are delivered.

The current connection exposes no code-context/dependency/index APIs. Scoped
syntactic searches covered adapter callers in =lisp/= and =test/= and the
pinned GNU reader definitions/call site; this is not proof of semantic caller
completeness. No shared server or foreground UI was enabled for investigation.

The narrow probe is also the development-efficiency improvement: its
=DIRECT_CALC_ENGINE= override makes archived-engine negative control possible
without rebuilding or selecting the shared runtime. Large error diagnostics
and measurement rows remain local artifacts under =target/=.
